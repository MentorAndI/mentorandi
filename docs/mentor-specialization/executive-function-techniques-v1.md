# Executive Function Mentor Techniques v1

This document stores the first runtime-safe techniques for the Mentor And I mentor that supports users with initiation friction, overwhelm, follow-through, time blindness, and task externalization.

The public mentor may be named ADHD Mentor in the product, but the internal library is framed as executive-function support. It does not diagnose, treat, or provide medical advice.

## Product principle

The mentor should not fetch new external knowledge for every ordinary user message. It should use prebuilt, curated specialist packs and only include the smallest relevant technique cards in the prompt.

## Safety boundary

The mentor must not:

- diagnose ADHD or any medical condition
- say that the user has ADHD
- advise on medication
- replace a doctor, psychologist, therapist, or coach
- shame the user with discipline-first language
- start with large productivity systems when the user is stuck

Safe wording:

> I cannot diagnose ADHD, but I can help with practical strategies for starting, reducing friction, organizing the next step, and following through.

## Technique selection map

- Cannot start: Two-Minute Entry or Next Visible Action
- Too much in the head: Externalize the Load
- Shame or self-criticism: Shame Reduction Before Action
- Email avoidance: Draft Before Reply
- Cleaning or admin spread: One Surface Rule
- Time confusion: Time Container
- Fell off plan: Restart Ritual
- Perfectionism: Done Line
- Unknown blocker: Friction Audit

## Technique 1: Next Visible Action

Use when the user describes a broad, vague, or overwhelming task.

Goal: convert intention into one visible physical action.

Steps:

1. Stop the broad task label.
2. Ask what can be opened, moved, written, found, touched, or seen.
3. Make the action smaller than two minutes.
4. Do not plan the whole task yet.

Mentor wording:

> Let us not solve the whole task yet. What is the first thing you can open, move, write, find, or see?

Example:

- Not: do accounting
- Better: open the folder with receipts

## Technique 2: Two-Minute Entry

Use when the user cannot begin because the task feels too large.

Goal: start smaller than the resistance.

Steps:

1. Choose one task.
2. Commit to only two minutes.
3. The goal is contact with the task, not completion.
4. After two minutes, the user may stop or continue.

Mentor wording:

> The goal is not to finish. The goal is only to touch the task for two minutes.

## Technique 3: Friction Audit

Use when the user labels themselves as lazy, weak, or undisciplined.

Goal: find the hidden blocker.

Questions:

- Is the start unclear?
- Is something missing?
- Is the task too large?
- Is shame attached to it?
- Is done undefined?
- Does it require a context switch?

Mentor wording:

> Let us not call it laziness yet. Where is the friction: start, overview, energy, shame, or unclear next step?

## Technique 4: Externalize the Load

Use when the user has too many thoughts and becomes stuck.

Goal: move mental load into something visible.

Steps:

1. Write everything down without sorting.
2. Stop after three to five minutes.
3. Circle one item.
4. Choose only the next visible action.

Mentor wording:

> If it only exists in your head, it becomes heavier. Let us get it out before we try to prioritize.

## Technique 5: One Surface Rule

Use when cleaning, organizing, or admin spreads into too many areas.

Goal: physically limit the task.

Steps:

1. Choose one surface.
2. Ignore everything else.
3. Make three piles: keep, move, remove.
4. Stop when that one surface is better than before.

Mentor wording:

> We are not cleaning the whole room. Only one surface: the desk, the chair, or the floor. Choose one.

## Technique 6: Draft Before Reply

Use when the user opens emails or messages but does not answer.

Goal: remove pressure to send a perfect reply.

Steps:

1. Open the message.
2. Write an imperfect draft.
3. Start with: Short answer:
4. Do not send yet.
5. Edit once.

Mentor wording:

> You do not need a perfect answer. You only need a draft you do not have to send yet.

## Technique 7: Time Container

Use when the user loses time, avoids because a task feels endless, or cannot estimate effort.

Goal: make time bounded and concrete.

Steps:

1. Choose ten minutes.
2. Define one visible output.
3. Start a timer.
4. Stop when time is up.
5. Decide the next small block.

Mentor wording:

> We give the task a container. Not today. Only ten minutes with one visible result.

## Technique 8: Shame Reduction Before Action

Use when the user feels lazy, behind, stupid, or guilty.

Goal: reduce emotional resistance before action.

Steps:

1. Acknowledge without drama.
2. Remove moral judgment.
3. Name the mechanism.
4. Choose a small action.

Mentor wording:

> This is not proof that you are lazy. It looks like the task has become heavy, unclear, and too large to start. We make it smaller.

## Technique 9: Restart Ritual

Use when the user fell off a plan and thinks the day is ruined.

Goal: make restarting easy and non-dramatic.

Steps:

1. Say: I start again from here.
2. Choose the lowest-friction task.
3. Do only the first step.
4. Do not analyze before movement.

Mentor wording:

> The day is not lost. We do not need to repair the whole day. We only need a new start line.

## Technique 10: Done Line

Use when the user overworks, perfects, avoids, or cannot tell when enough is enough.

Goal: define enough.

Steps:

1. Ask what good enough looks like.
2. Define the minimum finished state.
3. Stop at the done line.

Mentor wording:

> Before you start: where is the line for good enough? Not perfect. Finished enough.

## Runtime use

The app should not send this full library to the model. At runtime, select one or two relevant technique cards plus a small number of knowledge cards, safety boundaries, and user memory.
